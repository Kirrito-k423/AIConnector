# 0.7.9：诊断按单项 receipt 排队，取消全局空闲屏障

修复 [Issue #13](https://github.com/Kirrito-k423/AIConnector/issues/13)。0.7.8 原来的全局空闲条件会阻止诊断入队；长时间延迟还会使早期十秒窗口超出保留上限。

```text
本任务 Pi 完成 → 结果 ZIP → result → Mac 校验及 receipt
→ Windows 观察本任务 receipt → 冻结本任务诊断 ZIP
→ 低优先级队列 → 上传/不可变 SHA 对账
```

其他任务可继续 waiting/running，Advertise/Audit 重试不再阻止诊断入队。传输仍串行：前台操作优先，正在执行的请求不中断。持续前台负载可能推迟诊断发送，因此增加持久化的最多 12 次、24 小时预算，过期停止自动重试并留痕。期限只取消还未开始的诊断操作，不改变实际执行或已在途上传的语义。

已完成且有可信 receipt 的重复 confirmed outbox 记录会清理；事件、评论与 Claim 所有权继续保存。未决、拒绝、冲突和未闭环的记录保留。具体安全边界和 Windows 验收见 [Issue #13 修复说明](ISSUE-13-FIX.md)。

十秒计时继续在本地异步写入；诊断仍以单个 ZIP 统一回传，不加入十秒网络写入。全局日志轮转、2000 个相关事件和1000 个窗口的上限仍存在，回传后必须检查截断及时间覆盖，不能据后期窗口推断早期缺失区间。

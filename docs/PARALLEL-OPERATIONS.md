# 0.7 并行候选版：安装与一次验收

本版包含 0.6.5 对 Issue #7/#8 的修复。Windows 可以同时运行 1–8 个独立 Pi；新配置默认 4，旧配置没有该字段时保留 1。各任务仍使用独立运行目录、模型会话和结果 ZIP。

## 启用

1. 等已执行的 Pi 结束，使用原配置路径升级 AIConnector。升级保留密钥、Claim、任务记录和结果；不要清空状态。
2. SSH 并行需要配套的 simpleHtmlWatch 0.5 候选版，它提供 `simplehtmlwatch.reservations.v1`。保留原中台数据目录，尤其是 `tasks/`。旧中台仍可用于串行模式。
3. Windows 看板「Pi 配置」将“同时运行 Pi 数”先设为 2，保存后检查配置。检查中的 `reservations.ok` 必须为 true。对应本地配置为 `runner.maxConcurrentRuns`，范围 1–8。
4. 选择两个明确可用且互不相同的服务器探测入口，按原流程发布任务；确认两个 Pi 的实际时间区间重叠、目标机器不同、各自有 ZIP 和回执后，可将并发调至 4。

任务在等待资源时不调用模型。机器占用、等待原因和占用者在 Windows 任务详情中显示；页首显示 Pi 槽位使用量。任务执行完成与 ZIP 上传分开，GitHub 断网不阻塞已有 Pi 的监督与本地收尾。取得执行许可仍需经过单写入者的 Connector 队列；正在进行的网络调用不会被强行中断，新的 Claim 可能等待该次有界请求结束。

## 当前支持边界

- SSH 并行只开放固定 `machineId` 入口。group/任意机器入口保留串行使用，不能在并行模式中绕过预留。
- 每台物理机 1 个排他任务。simpleHtmlWatch 对相同 host 的不同端口互斥；不同地址属于同一物理机时，在本机中台配置相同 `resourceId`，不能依赖入口名称去重。
- 不同服务器共用 NFS 工作目录或其他共享写入资源时，给相关本地入口配置相同 `resourceKeys`，例如 `["workspace:shared-project"]`。这些额外锁在本节点内互斥；程序不会从任意 shell 自动推断共享目录。
- 普通 command 与 maintenance 入口保守地占用本节点全局锁，其他 Pi 等待；内置 CPU smoke 的工作目录独立，可并行。
- 预留由 simpleHtmlWatch 持久保存，覆盖它的 `/api/tasks` 接口。人工 SSH、即时批量命令 `/api/executions`、自定义监控指令、另一套独立中台需自行遵守资源安排，不在此锁域内。
- 每项任务保留已有模型预算。并发数限制同时活跃的 Pi；跨任务精确 token/费用配额代理、provider 统一 429 冷却、多机原子预留、Pi 挂起恢复和 Mac 远端实时心跳尚未交付。

## 恢复与解锁

主服务重启读取原运行记录并继续观察原 Pi，不重新派发。旧版留下的活动/未知任务无法证明资源范围时，先以全局锁保护，完成核对后才逐步开放并行。

Pi 结束不表示服务器结束。若远端任务 unknown，结果可以照常回传 blocked，但对应机器继续显示占用；其他已映射机器可推进。核对真实远端进程后，在 simpleHtmlWatch 按原 task ID 查询或执行其已有的人工“确认远端已停止”流程。控制器确认结束后，AIConnector 自动重试释放原预留；不要删除文件或换一个 ID 重发原命令。

预留没有自动过期；释放后的 ID 不可复用。任何仍未结束的关联 SSH 作业都会使释放返回 409。公网上传与 Mac receipt 不占机器使用权。

## 验收证据

开发回归包含真实独立 Pi 进程并行、4 个槽位填满、监督器重建后不重复启动、慢上传期间继续补位、丢失预留响应后按原 ID 对账、不同机器互不阻塞、同一机器排队，以及旧版 unknown 保守隔离。simpleHtmlWatch 使用 Go race 检查抢锁、持久恢复、别名互斥、释放拒绝、旧 owner 不能再次执行和 API 鉴权。

这些测试使用受控模型与服务器 fixture。真实 Windows 公司代理和 A5 硬件的并行验收仍需要升级后运行上述两机器检查，不能用 CPU fixture 或页面计数代替。

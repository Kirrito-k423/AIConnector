# Windows Issue 17 修补候选

Issue 17 报告的 `FILESYSTEM_IO_ERROR` 位于 `Connector.ps1` 原第 200 行，对应已存在状态文件的原子替换。`HTTP_OK` 只表示前一 HTTP 请求成功，不能排除随后的文件保存失败。现有报告未包含底层 Windows 错误码，因此尚不能断言实际占用者或磁盘根因。

修订包含两个独立机制：

1. 原子替换遇到 Windows 共享冲突或锁冲突（32、33）时，针对同一个临时文件最多尝试 8 次，累计等待不超过 450 毫秒。失败仍保留原状态文件；其他 I/O 错误立即返回。
2. 能力公告的待发布快照超过 30 分钟后，完整读回公告，再用当前本地能力生成新快照。旧 `uncertain` 或 `rejected` 记录保留并记录被替代时间。此机制只处理能力观察，不重试未知任务创建、Release、领取或上传。

`UPLOAD_REJECTED` 的原始拒绝记录保持不变。修补件输出脱敏的状态数量、HTTP 码与原生错误码，用于确定是否还需处理明确拒绝的旧交付；不重置全部上传状态。

## 使用

将 `AIConnector-Issue17-Windows-Patch.zip` 全部解压，保持原 Windows AIConnector 看板运行，双击 `Repair-Issue17.cmd`。

工具核对原脚本 SHA，沿用现有配置及凭据，并先执行正常升级流程的工作进程检查。存在活动工作进程时拒绝安装；通过检查后正常排空并关闭本机服务，备份原脚本和包清单，再替换脚本、更新清单并启动原服务。配置、任务账本、运行编号和实验产物不在修改范围内。任何未知执行记录都保留，工具不强制终止进程。

成功输出只确认修补安装及 Windows 本机 API 恢复。新公告是否抵达 Mac、文件取件是否完成，仍需分别验证。`issue17-diagnostic.json` 留在解压目录，只包含脱敏诊断；实际接收端验收尚未完成。

## 验证范围

故障注入已在真实 PowerShell 原子写入函数中复现单次共享冲突失败；原版过期公告用例复现 `PROVISION_UNCERTAIN_OR_REJECTED`。候选版局部用例通过。安装辅助工具覆盖版本拒绝、备份、包清单更新、失败回滚、中文及空格路径和脱敏输出。Windows 5.1 CI 与用户机器验收分别记录，不以 Mac fixture 替代。
